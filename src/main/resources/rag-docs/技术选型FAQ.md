# 技术选型 FAQ

## 为什么对话模型选 DeepSeek V4？

DeepSeek V4 通过 OpenAI 兼容协议接入，Spring AI 官方原生支持，配置简单；V4 具备较强的推理与中文能力，且价格友好。它支持多模态输入（可理解图片），但不提供 embedding 和文生图能力。

## 为什么向量化用本地 Ollama 的 bge-m3？

bge-m3 是中文检索效果优秀的嵌入模型，通过本地 Ollama 运行，完全免费、无需云密钥，也不会把公司文档内容上传到第三方。对于知识库这类涉及私有资料的场景，本地 embedding 在成本和数据安全上都是更优选择。

## 为什么记忆要先存 MySQL 再做双表分离？

早期记忆放在内存里，应用重启就丢失，且无法跨实例共享。迁移到 MySQL 后可以持久化。但 Spring AI 的滑动窗口记忆（MessageWindowChatMemory）超窗口会物理删除老消息，导致历史"缺头"。因此进一步做了双表分离：chat_memory 只存喂模型的滑动窗口，chat_log 存完整的对话日志，互不干扰。

## 结构化输出有什么用？

大模型默认返回自由文本，只有人能读、程序无法直接消费。结构化输出（BeanOutputConverter）把一句话需求解析成规整的 Java 对象，才能落库、流转、做条件判断，是 Agent 工作台能"干活"的前提。

## 阶段 3 的向量库为什么先用内存版？

SimpleVectorStore 是 Spring AI 提供的内存向量库，适合演示与测试，零额外依赖，应用启动时自动从 rag-docs 加载文档建索引。生产环境可后续替换为 pgvector、Redis 等持久化向量数据库。
